# Forge R&D: контролируемый проект

Это искусственный проект с намеренными дефектами. Он не является исходным кодом Forge Action.

Проверка: `node --test benchmark/test/cart.test.cjs` из корня репозитория.
Ожидаемый исходный результат: 3 успешных и 3 падающих теста.

## Задачи для Forge после подключения сервиса

1. **Количество товаров.** Исправить `total`: сумма в целых копейках должна учитывать `quantity`. Не менять тесты и не добавлять зависимости. После исправления проходят первые три теста.
2. **Пагинация.** Исправить `paginate`: нумерация страниц начинается с 1. Последняя страница может быть неполной, страница за границей массива возвращает пустой массив. Не менять тесты. После исправления проходят все 6 тестов.
3. **Отрицательные сценарии.** На отдельной ветке добавить валидацию: отрицательные цены, неположительное/нецелое количество, page/pageSize <= 0 или нецелые должны приводить к RangeError. Добавить тесты. Исходные 6 тестов должны проходить.

Для сравнения моделей: один и тот же исходный commit, одна задача, новая ветка и новый job, минимум 3 повторения на каждую реально доступную модель. Сохранять запрошенную и фактическую модель, input/output/cache tokens, стоимость от провайдера, время очереди/установки/генерации/проверки, tool calls, retries, ошибки и результаты тестов.

Повторный запуск wrapper, повторный tool call и повторная попытка GitHub Actions — разные события. Луп: три одинаковых действия с одинаковой ошибкой без изменения файлов или контекста. Без сырых логов модели фиксировать «нет данных», не 0.
